# Git / GitHub 学習ワークフロー

このリポジトリは Git / GitHub の練習を目的としています。作業する際は以下の方針に従ってください。

## ブランチ運用

- `main` が基準ブランチ。作業は必ず `main` から分岐したブランチ上で行い、直接 `main` にコミットしない。
- ブランチ名は目的が分かる名前にする(例: `update-readme`, `fix-outlook-draft`)。
- ブランチを切る際は `git switch -c <branch-name>` を使う(`checkout -b` の後継で、切り替え専用コマンドのため意図が明確)。

## コミット

- 1コミット1目的を意識する(無関係な変更を1つのコミットにまとめない)。
- コミットメッセージは「何を」より「なぜ」を書く。
- `git add` は対象ファイルを明示して行い、`git add -A` / `git add .` は避ける(意図しないファイルの混入を防ぐため)。

## プルリクエスト

- ローカルで完結させず、変更は `git push` してPRを作成する練習をする。
- PRの説明には変更内容とその理由を書く。
- マージ前に `git diff` / `git log` で差分を確認する習慣をつける。

## 進め方の原則

- 各Git操作(コミット、ブランチ作成、マージ、PRなど)は省略せず、なぜその手順・コマンドを選んだのかを説明しながら進める。
- ショートカット(force push、`--no-verify` など)より、正しい手順を優先する。
